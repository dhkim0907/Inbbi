# 작업: Figma ‘인삐 UI’ 기반 캘린더·공지 UI 구현

상태: 캘린더·공지 1차 구현 및 검증 완료, 후속 시각 검토·기존 실패 별도 관리

## 목표와 허용 범위

Figma ‘인삐 UI’를 디자인 기준으로 삼아 캘린더·공지 화면과 해당 화면에서 사용하는 아이콘을 Flutter로 구현한다. 디자인 확인 → 구현 단위 확정 → 코드 수정 → 자동 테스트 → 화면 비교 → 결과 기록을 각 단위마다 반복한다.

- 확인한 원본: [인삐 UI](https://www.figma.com/design/DVFSfaYxtHpZ9VMFl8miuG/인삐-UI?node-id=0-1). 파일 키 `DVFSfaYxtHpZ9VMFl8miuG`. 조회일 2026-10-18.
- 실제 조회한 페이지: 캘린더 `0:1` (모바일 15개·웹 17개 프레임), 공지 `9:7264` (모바일 22개·웹 17개 프레임). 초기 페이지 목록에 공지가 나타나지 않았으나 사용자가 제공한 페이지 URL로 직접 조회했다.
- 아이콘 페이지 자체의 ID는 아직 미확인이다. 구현 대상 화면에 포함된 원본 아이콘은 디자인 컨텍스트에서 확인하고 내려받았다.
- UI 변경 허용 범위: 해당 Figma 페이지에서 확인한 캘린더·공지 화면과 두 화면에 필요한 아이콘. 모든 프레임을 자동으로 구현 대상으로 간주하지 않고 실제 화면·상태와 연결해 목록을 확정한다.
- 보존할 동작: 일정 조회·월 이동·날짜 선택·종류 필터·일정 추가/수정/삭제, 공지 검색·탭 필터, 계정 연결, 알림 배지·화면 이동, 840 논리 픽셀 반응형 기준.
- 범위 밖: 홈·강의·설정·로그인 UI, 앱 런처 아이콘, 서버·Google API 계약, 인증·알림 전송 방식 변경, Figma 원본 수정, Git 커밋·푸시.
- 공통 테마나 내비게이션 변경이 범위 밖 화면에도 영향을 주면 먼저 화면 전용 구성을 검토한다. 범위 밖 UI 변경이 반드시 필요하면 사용자에게 이유와 범위를 설명하고 승인을 받는다.

## 기존 코드 조사

- 캘린더는 `CalendarPage`가 `BaseView`, `MonthCalendarGrid`, `CalendarWeekEventBars`, `NotificationBellButton`을 조합한다. 일정 동작은 `CalendarController`와 서비스에 위임한다.
- 공지는 `NoticeFeedPage`에 모바일/데스크톱 레이아웃, 검색과 탭 필터가 있다. 현재 화면 내 샘플 목록을 사용하므로 UI 작업을 실제 공지 서버 연동 완료로 표시하지 않는다.
- 재사용 후보: `AppColors`, `AppTextStyles`, `AppTheme`, `AppBreakpoints`, `MaxWidthBody`, `TitledCard`, `ResponsiveCardGrid`와 기존 달력·알림 위젯.
- `MainTabShell`의 캘린더 인덱스는 1, 공지는 2다. UI 적용을 위해 라우트·인덱스를 바꾸지 않는다.
- 기존 캘린더 서비스·입력·상세·날짜 선택·기간 표시 테스트를 재사용한다. 기존 공지 전용 테스트가 없어 `test/features/notice_feed/`에 검색·필터·등록 흐름과 저장 서비스 테스트를 추가했다.
- 저장소에는 기존 미커밋 변경이 많다. 작업 시작과 각 구현 단위 완료 시 변경 목록을 비교하고 기존 변경을 유지한다.

## 구현 순서와 완료 조건

### 1. 디자인 확인 및 구현 단위 확정

- [x] 기존 하네스 문서, 관련 화면·공통 위젯·테마·테스트 구조 확인
- [x] Figma 파일 링크와 추가 페이지 링크로 ‘인삐 UI’의 캘린더·공지 구성 확인
- [x] 이번 구현 기준인 대표 프레임의 디자인 컨텍스트와 스크린샷 확보
- [x] 모바일/데스크톱 기본·필터·빈 목록·상세·입력 및 수집처 설정 상태 구분
- [x] 이번 구현의 프레임 → Flutter 위젯 → 검증 시나리오 대응 표 작성

`figma-design-to-code` 스킬을 사용한다. 최초 디자인 컨텍스트 조회에 스크린샷을 요청하고, 누락 시 별도로 확보한다. 응답이 불완전하면 화면에 보이는 하위 노드의 상세 정보를 확보한 뒤 구현한다. 이미 확인한 정보를 문서에 남겨 불필요한 재조회를 줄인다.

디자인에 한쪽 레이아웃만 있으면 기존 다른 쪽 레이아웃과 기능을 유지하고, 화면 폭에 따른 필수 배치 조정만 적용한다. 다른 쪽 화면의 새로운 시각 디자인을 임의로 만들지 않는다.

### 2. 아이콘·디자인 값 대응

- [x] 실제 사용하는 원본 아이콘을 기존 아이콘·에셋과 대조
- [x] MCP 응답의 다운로드 지침에 따라 SVG를 로컬에 저장하고 `pubspec.yaml`에 등록
- [x] 원본 SVG 크기, 비어 있지 않은 파일, 호출 위치와 렌더링·버튼 의미 확인

아이콘 페이지 전체를 앱 전체에 일괄 적용하지 않는다. 캘린더·공지의 해당 위치에 사용되는 아이콘만 반영한다. 원본과 일치하지 않는 Material 아이콘으로 임의 대체하거나 디자인 스크린샷을 화면 이미지로 넣지 않는다. SVG가 필요한지는 실제 에셋을 확인한 뒤 결정하고 의존성은 필요한 경우에만 추가한다. 임시 Figma 에셋 URL을 앱 코드에 남기지 않는다.

### 3. 캘린더 화면 구현

- [x] 확인한 캘린더 기본 프레임을 기존 공통 위젯을 활용해 구현
- [x] 일정·할일 입력 및 상세 창의 크기·배치 반영
- [x] 날짜 선택·월 경계·필터·완료 상태·일정 조작 회귀 검증
- [x] 대표 화면 관련 테스트와 모바일/데스크톱 렌더링 확인

UI 변경이 서비스 동작을 바꾸지 않도록 한다. 필요한 경우 위젯 매개변수를 확장하되 기존 호출부의 기본 표현과 동작을 유지한다.

### 4. 공지 화면 구현

- [x] 확인한 공지 프레임을 기존 반응형 레이아웃에 반영
- [x] 검색·탭 선택·검색 결과 없음 및 목록 복귀 동작 검증
- [x] 긴 검색어와 좁은 화면의 분류 가로 스크롤·레이아웃 예외 확인
- [x] 수집처 등록 3단계, 필수값·URL 검증, 날짜 생략, 로컬 저장·복원·중복·저장 실패·삭제 정책 테스트
- [x] 대표 화면 관련 테스트와 모바일/데스크톱 렌더링 확인

디자인에서 확인된 수집처 등록·관리·색상·수집 여부 설정은 로컬 예시 흐름으로 구현했다. 입력한 웹사이트에 접속하거나 실제 공지를 수집하지 않는다. CSS 셀렉터 검증도 제공한 예시 행(`.sample-row`, `a`, `time`)에 한정하며 범용 CSS 파서가 아니다. 실제 수집·공지 상세 API·공지의 일정 추가는 별도 작업이다.

## 렌더링 재현 및 에셋 추적

```sh
INBBI_UI_REVIEW=1 flutter test --no-pub \
  test/features/calendar/calendar_figma_page_test.dart \
  test/features/notice_feed/notice_feed_page_test.dart
```

- 실제 프로젝트의 NotoSansKR·Material Icons 폰트를 로드한 Flutter 위젯 렌더링을 `build/ui_review/`에 저장한다. 생성물은 커밋하지 않는다.
- 기본 화면: `calendar-390.png`, `calendar-1207.png`, `notice-390.png`, `notice-1207.png`.

- 390·839·840·1207 논리 픽셀로 새 흐름을 검증한다. 1207은 원본 웹 1425에서 사이드바 218을 제외한 콘텐츠 너비이며, 기존 테스트의 1280 너비도 유지한다.
- 캘린더 SVG: `bell`(21), `previous`(21), `next`(21), `date`(23), `empty`(35), `add`(27), `close`(21), `input_date`(원본 치수), `input_time`(원본 치수). `CalendarDesignIcon`과 실제 버튼·빈 상태에서 사용한다.

- 색상은 캘린더 전용 `CalendarDesign`과 공지 전용 구성에 한정한다. 공통 테마와 홈 미니 캘린더의 기본 표현을 변경하지 않는다.

## 보존한 기능과 원본 디자인의 차이

- 공통 사이드바·하단 내비게이션은 다른 화면에도 영향을 주므로 그대로 유지했다. 원본 프레임의 전체 셸을 앱 전체에 일괄 적용하지 않았다.
- 기존 일정 새로고침 버튼과 Google/앱 저장 대상 선택 기능을 유지했다. 원본과 비교할 때 이 부가 컨트롤도 고려해야 한다. 할일의 저장 대상을 사용자 선택 없이 강제로 변경하지 않는다.
- 캘린더의 ‘선택한 날짜 이후 7일’ 미완료 목록은 선택 당일 다음 날부터 계산한다. 실제 현재 월에 로드된 데이터 범위에서 표시하며 다음 월 API까지 추가 조회하는 기능은 넣지 않았다.
- 공지는 테스트용 목록이다. 수집 여부 스위치는 로컬 설정을 저장하며 끄더라도 기존 예시 목록은 유지한다. 예시 미리보기는 실제 웹사이트 조회 성공을 의미하지 않는다.
- 설정은 `inbbi.notice_sources.v1` 키에 로컬 저장한다. 테스트는 저장소 대역으로 영속화 계약을 검증했으며, 실제 브라우저 데이터 삭제·기기 간 동기화·계정별 분리는 검증하지 않았다.

## 남은 사항

- 전체 원본 프레임 각각의 시각적 완성도 확인과 미세 간격 조정. 현재 대표 프레임 렌더링과 핵심 동작을 검증했으며 모든 상태의 완전한 일치를 선언하지 않는다.
- 별도 ‘아이콘’ 페이지의 ID 확인과 전체 라이브러리 정리. 현재 화면에 실제 쓰는 원본 SVG는 반영했다.
- 실제 Google 계정 연결·공지 서버 수집·실기기 및 실제 브라우저 수동 검증은 이번 범위에서 실행하지 않았다.
- 기존 인증·설정·푸시 관련 테스트 실패와 강의 화면 서식 불일치는 범위 밖 작업으로 남긴다. 해당 UI를 임의로 바꾸거나 테스트 기대값만 완화하지 않는다.
