## 검증 기록

- 하네스 문서는 작업 시작 시 사용자 삭제 상태이므로 `git show HEAD:docs/harness_engineering.md`로 읽고 복원하지 않았다.
- 추가 Figma 상세 조회 9건은 Starter 플랜 MCP 호출 한도로 실패했다. 별도 연결에서도 같은 제한을 확인했다. 메타데이터만 확보한 프레임을 상세 구현·시각 검증 완료로 표시하지 않는다.
- 사용자 재개 요청 후 `9:2` 데스크톱 프레임의 상세 컨텍스트·스크린샷을 다시 요청했으나 동일한 Starter 플랜 한도 오류가 반환됐다. 로컬 참조 파일도 확인했으며, 남은 프레임의 상세 자료는 저장되어 있지 않았다. 이번 재시도에서는 UI 코드를 추가로 변경하지 않았다. 추가 진행에는 Figma MCP 조회 가능 상태 복구 또는 상세 수치·에셋을 포함한 디자인 자료가 필요하다.

### 반영한 차이

- 캘린더 모바일: 필터 5개를 동일한 너비·간격 5·높이 39로 배치하고 필터 전후 여백을 수정했다. 기존 `ActionChip`을 재사용하고 데스크톱 필터의 기존 표현을 보존했다.
- 캘린더 카드: 제목·종류·상태 글자 크기와 카드 여백·모서리·세로 줄을 보완하고 누락된 장소·종일 일정 기간·메모를 표시했다. 종일 일정의 배타적 종료일은 하루를 빼서 표시한다.
- 미완료 목록: 날짜 제목별로 묶고 마감 순으로 정렬한다. 기간 항목은 마감 날짜에 한 번만 표시하고 완료 항목을 제외한다. 원본처럼 전체 분류에서 표시하며, 특정 분류에서는 선택 날짜 목록을 표시한다.
- 공지 미리보기: 원형 단계 번호·연결선, 결과 행 높이·구분선·제목·날짜·URL, 안내 배경, 버튼 여백·글꼴을 수정했다. 단계가 바뀌면 이전 단계의 스크롤 위치를 이어받지 않는다.
- 공통 테마·내비게이션·인증·서비스 계약은 수정하지 않았다. 원본의 Segoe UI·GulimChe 대신 프로젝트에 등록된 NotoSansKR을 사용한다. 이 글꼴 차이와 전체 셸의 차이는 남아 있다.

## 남은 사항

- Figma 추가 상세 조회 제한이 해제되어야 나머지 프레임과 공통 내비게이션·날짜 이동·추가 메뉴의 정확한 비교가 가능하다.
- 캘린더·공지 전체 71개 프레임의 시각적 일치가 완료된 것은 아니다. 화면별 나머지 상태, 전용 아이콘 페이지, 데스크톱 원본 전체 셸을 추가로 확인해야 한다.
- 실제 계정 연결·알림 전달 검증은 UI 비교 범위 밖이다.

## 첨부 이미지 기반 후속 작업

사용자가 MCP 연결 없이 진행하도록 캘린더 웹·앱, 공지 웹·앱의 전체 프레임 이미지를 제공했다. 이후 작업은 첨부 이미지에서 확인되는 배치·상태와 기존 로컬 자료를 기준으로 진행했다. Figma MCP를 다시 호출하지 않았다. 위의 MCP 제한은 이 후속 작업의 중단 사유가 아니다.

이미지는 채팅에서 각각 2048×93, 2048×833, 2048×137, 2048×425로 축소되었다. 모바일 개별 프레임 폭은 약 73~107픽셀, 웹 프레임 폭은 약 112픽셀로 보이므로 세부 문구·아이콘 경로·미세 간격 전체를 판독할 수는 없다. 원본 픽셀 단위 완전 일치와 모든 상태의 구현 완료를 선언하지 않는다.

| 첨부 참조 | 확인한 차이와 반영 | 코드 | 검증 |
|---|---|---|---|
| 캘린더 앱·웹의 분류 선택 화면 | 강의·과제·일정·할일의 선택 색상을 각 분류 색상으로 변경 | `calendar_page.dart` | 기존 종류 필터·색상 테스트 |
