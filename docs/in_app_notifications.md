# 앱 내부 알림

## 구현 범위

Android·iOS·웹 앱 내부 목록과 읽음 상태를 지원한다. 서버 푸시를 통한 시스템 알림 설정과 테스트 절차는 [앱 외부 알림](push_notifications.md)을 참고한다. 로컬 예약은 지원하지 않는다. 기존 고정 예시 목록 대신 최초 실행에는 빈 목록을 표시한다. 상단 벨은 알림 탭을 열며, 미확인 개수를 표시한다.

알림을 선택하면 저장 성공 후 읽음으로 변경하고 마감은 캘린더, 강의는 강의 관리, 맞춤 공지는 공지 탭으로 이동한다. 현재 상세 화면과 실제 일정·공지 수신 서비스는 없어 해당 목록 탭까지 이동한다.

## 수신 연결 및 저장 정책

`NotificationService.receive(AppNotification(...))`로 이벤트를 등록한다. UI에서는 `NotificationScope.of(context)`로 앱 전역 서비스를 참조한다. 추후 동기화 서비스에는 같은 서비스 인스턴스를 주입한다. 동일 사건에는 동일한 ID(예: `assignment:123:deadline:2026-09-28`)를 전달해야 한다. 기존 ID 재수신은 내용과 읽음 상태를 바꾸지 않는다. 추후 외부 알림 수신도 동일한 ID를 사용해야 하며, 운영체제 배너 중복 방지는 별도로 구현해야 한다.

목록은 최신순으로 정렬하며 전체 목록과 읽음 상태를 기기 로컬에 저장한다. 자동 만료·삭제는 없으며 앱 데이터 또는 브라우저 사이트 데이터 삭제 시 사라진다. 현재 인증이 목업이므로 저장은 설치/브라우저 단위다. 실제 다중 계정 인증 연결 전 사용자별 저장 키와 로그아웃 정책을 추가해야 한다.

저장 작업은 순차 실행하며 실패 시 기존 상태를 보존하고 오류를 표시한다. 사용자는 같은 동작을 다시 시도할 수 있다. 초기 로드 실패는 '다시 시도' 버튼으로 재실행한다. 손상된 저장 데이터는 자동으로 덮어쓰지 않는다.

저장 SDK는 `shared_preferences`의 `SharedPreferencesAsync`를 사용한다. 공식 문서상 Android SDK 24+, iOS 13.0+, 웹을 지원하며 웹은 LocalStorage를 사용한다. 중요한 데이터의 영구 보존을 보장하는 저장소는 아니다.
공식 문서: https://pub.dev/packages/shared_preferences

## 검증 결과 (2026-09-27)

- `flutter analyze`: 통과.
- `flutter test`: 7개 통과.
- 메모리 저장소 테스트: 동시 중복 수신, 읽음 상태, 서비스 재생성 후 복원, 저장 실패와 재시도, 손상된 데이터 보호 통과.
- 위젯 테스트: 너비 390, 839, 840, 1280에서 빈 목록, 카테고리 필터, 미확인 필터, 읽음 처리, 캘린더 이동 콜백, 배지 갱신 및 레이아웃 예외 없음 확인.
- 실제 Android/iOS 기기 및 브라우저 재실행 시 영구 저장, 실제 서비스 수신, 외부 알림과의 동시 전달은 미검증. 자동화 테스트는 메모리 저장소와 테스트 이벤트를 사용했다.

## 수동 확인 절차

1. 개발 모드로 앱을 실행하고 상단 벨 또는 데스크톱 알림 메뉴를 선택한다.
2. '테스트 알림'을 누른다. 목록과 미확인 개수가 함께 증가해야 한다. 이 버튼은 디버그 빌드에서만 표시된다.
3. 알림을 선택한다. 캘린더로 이동하고 배지가 감소해야 한다.
4. 알림으로 돌아와 '읽지 않음' 필터 및 '모두 읽음'을 확인한다.
5. 앱을 완전히 재실행한다. 저장된 목록과 읽음 상태가 복원되어야 한다.

Firebase 설정 후 서버 푸시로 알림을 수신할 수 있다. 실제 일정·공지의 자동 이벤트 생성 서비스 연결은 별도로 필요하다.
